# M1 spec — executable job, 4 executed faults, snapshot, tools, oracle, re-execution

Read with `the design spec` §5.2, §6, §7 and `the project rules`. Base the job on
`scripts/m0/gloo_fault_proof.py` (verified on macOS: spawn, own process polling — `mp` join
SIGTERMs siblings — free port, MASTER_ADDR=127.0.0.1, own per-rank JSONL trace).

Keep it small and plain. No OpenEnv/Inspect/MLX imports anywhere in M1 code.

## Packages

```
jobs/
  config.py      JobConfig (pydantic or frozen dataclass): world_size, steps, seed, hidden, lr,
                 ckpt_every, ckpt_format_version, shard_layout ("replicated"|"split"),
                 pg_timeout_s, watchdog_s, resume_from: ckpt_id | None,
                 rank_overrides: {rank: {key: value}} — realistic per-rank overrides; most are harmless
                 (log_level, profile, dataloader_prefetch) and act as red herrings. COLLECTIVE_MISMATCH is
                 injected as a harmful override (e.g. grad_sync: "broadcast" | "skip_last_bucket") on one
                 rank, effective from a seeded step (`grad_sync_from_step`). There is no fault-named key
                 anywhere in the config the agent sees.
  train.py       worker(rank, cfg, job_dir): Gloo DP loop on a toy MLP; per-rank structured log
                 (logs/rank{r}.jsonl) and collective trace (trace/rank{r}.jsonl); checkpoints under
                 ckpt/<ckpt_id>/ with shard files + manifest entry; resume_from loads + validates.
  launcher.py    run_job(cfg, job_dir) -> JobResult: spawn, poll, watchdog kill, per-rank exit code,
                 status, exception type/first line, last_step. Never hangs.
  resubmit.py    resubmit(job_dir, idempotency_key: str | None) -> ResubmitResult. Owns job_dir state:
                 job_dir/.lock (json: pid, port, run_id, started_at_step), job_dir/ckpt/MANIFEST.json
                 (list of entries {ckpt_id, step, world_size, format_version, shards:[{file, sha256, shape}]}),
                 job_dir/runs/<run_id>/. Refuses to start if .lock exists ("lock held by run_id=… pid=…").
                 Without idempotency_key, resubmit resumes from the checkpoint recorded at the *start* of
                 the preempted run (runs/<run_id>/start.json) rather than the latest manifest entry, so
                 it replays already-committed steps and re-appends manifest entries for them
                 (NONIDEMPOTENT). With a key it resumes from the latest valid entry and skips
                 (key, step) work already recorded.
  manifest.py    load/validate MANIFEST.json: unique ckpt_id, monotonic step, sha256 matches, shapes
                 consistent with world_size/shard_layout. Validation failure is a real error the job
                 hits on resume.
  faults/        one module per fault: build(seed, variant) -> FaultSpec(cfg_overrides, prepare_fn)
                 where prepare_fn(job_dir) sets up pre-existing state (stale lock, prior checkpoint, ...).
                 Variants: 2 per fault, e.g. COLLECTIVE_MISMATCH: (broadcast vs all_reduce) and
                 (rank skips one all_reduce); faulty rank and step chosen from seed.
  reexec.py      verify_fix(snapshot, actions) -> FixOutcome(ok, params_match_reference, no_duplicate_updates,
                 lost_steps, ranks_consistent, detail): copy the snapshot's PRIVATE fixture to a temp dir and apply
                 actions IN ORDER. Only `restart_from_ckpt` / `resubmit` relaunch the job, through resubmit.py
                 (lock check, manifest validation on resume) - never a direct run_job. No relaunch action => not ok.
                 ok = relaunched job completes N steps AND recovery is correct against an uninterrupted reference
                 run of the same scenario (fixture/reference.json, computed at execute time):
                   1. checksum over params + optimizer (momentum) state + global step is bit-identical to the
                      reference (data position is a pure function of (seed, rank, step));
                   2. manifest valid (unique, strictly increasing steps) and the recovered run applied every step in
                      [resume, N) exactly once on every rank;
                   3. lost_steps = furthest progress before the fix - resume step <= ckpt_every;
                   4. all ranks end with the same checksum.
                 verify_fix(snapshot, relaunch-only) must be not ok for every fault (test 3).
traindoctor_env/
  scenario.py    Scenario = (seed, fault label, variant, world_size). make_scenario(seed) for M1 picks
                 among the 4 faults. Ground truth lives in a separate Truth object, never in the snapshot.
  snapshot.py    execute(scenario, out_dir) -> Snapshot: runs the faulty job ONCE (plus the preemption /
                 resubmit sequence where the fault needs it), then captures an immutable snapshot:
                 records.jsonl, config.json (+ prev_config.json), manifest copy, process states,
                 scheduler events (job submitted / preempted / resubmitted — executed, from our own
                 resubmit.py). Every record: {id, kind, rank, step, text, source: "executed"}.
                 Also writes a PRIVATE immutable fixture/ (frozen job_dir: config, ckpt shards,
                 MANIFEST.json, .lock, runs/) and truth.json. Neither is readable through any tool;
                 only verify_fix and oracle use them. Snapshot = public/ + fixture/ + truth.json.
  tools.py       Episode (plain Python): reset(snapshot) -> obs; step(action: dict) -> (obs, done);
                 state() -> dict. Read tools: job_status, job_config, diff_config, rank_timeline(ranks,
                 window), collective_trace(step), grep_logs(pattern, ranks, window), ckpt_manifest,
                 process_state(rank), scheduler_events. Fix tools: patch_config(key, value),
                 clean_stale_state, restart_from_ckpt(ckpt_id), resubmit(idempotency_key), kill_ranks(ranks),
                 escalate(reason). End: submit_diagnosis(label, evidence_ids, fix_summary), finish.
                 (cordon_node and node_health arrive with the simulator in M2.)
                 Reads return text ≤ ~400 tokens (truncate deterministically, say "truncated"). Fix tools are
                 shape-validated only and return a uniform ack ("recorded") — no correctness feedback.
                 Episode tracks: actions (ordered), observed_ids (only IDs actually returned to the agent).
                 Read-only replay ends at the first fix action: Episode then makes a working copy of the fixture,
                 applies each fix through the real resubmit path (same Replay code as verify_fix), captures a fresh
                 public snapshot (ids from (seed, phase, index)) and serves later reads from it only.
  oracle.py      reference_solution(snapshot, truth) -> (label, evidence_ids, actions). Allowed to read truth.
tests/           see below
.github/workflows/ci.yml   ubuntu, Python 3.12, CPU torch, `pytest -q`.
```

## Determinism rules (load-bearing)

- Same seed → byte-identical public snapshot (`records.jsonl`, `config.json`, manifest copy,
  scheduler events) across re-executions, computed over CANONICAL failure records: map each
  rank's exception to a class (COLLECTIVE_TIMEOUT, PEER_CLOSED, SHAPE_ERROR, MANIFEST_INVALID,
  LOCK_HELD, ...). Do not require every rank to fail the same way (after the first rank exits,
  peers may see connection-closed instead of their own timeout). The deterministic diagnostic
  signal is our own collective trace (which op each rank entered at each seq), which does not
  depend on failure timing; per-rank trace records after the first error are dropped if their
  presence is timing-dependent. If byte-identity still flakes, the determinism test must fail
  loudly — do not weaken it. Wall-clock values (timestamps, durations, t_fail) never go into the snapshot. Use
  logical time: (step, seq) ordering; exception text with paths/addresses normalized (strip
  build paths like `/Users/runner/work/...`, hex addresses, ports, pids).
- Evidence IDs are opaque and must not encode cause: e.g. `"E" + sha256(seed, record_index)[:6]`.
  Record order is deterministic (sort by (kind, rank, step, seq)).
- Ports/pids may differ between runs; they must never appear in snapshot text.

## The 4 faults (each must really happen in the executed job)

| Label | Executed mechanism | Correct fix (actions) |
|---|---|---|
| COLLECTIVE_MISMATCH | harmful `rank_overrides[r].grad_sync` from step s → rank r enters a different collective → Gloo timeout | `patch_config("rank_overrides.<r>.grad_sync", <default>)` (or remove that override) then `restart_from_ckpt(<latest valid>)` |
| SHARDING_MISCONFIG | job resumes with world_size changed vs the checkpoint's split shards → shape error at load | `patch_config("world_size", <ckpt world_size>)` then `restart_from_ckpt(...)` |
| PREEMPTION_NO_CLEANUP | preempted run (killed) leaves `.lock` → resubmit refuses | `clean_stale_state` then `resubmit(idempotency_key=...)` |
| NONIDEMPOTENT_RESUBMIT | preempted run; scheduler force-clears the lock and auto-resubmits without key → replays committed steps, duplicate manifest entries → next resume fails validation | `clean_stale_state` (repairs manifest: dedupe) then `resubmit(idempotency_key=...)` |

Use short PG timeouts in tests (3 s) so CI is fast. `clean_stale_state` removes a lock only if the
owning pid is not alive and dedupes manifest entries; it must not delete valid checkpoints.

## Tests (assert rules from the spec, not current output)

1. `test_fault_reproducible[label×variant]`: execute same seed 2× → byte-identical snapshot files;
   the failure actually occurred (job did not complete; error class matches the mechanism).
2. `test_oracle_fix_verified_by_reexecution[label]`: verify_fix(oracle actions) → ok.
3. `test_wrong_fix_fails[label]`: a plausible wrong fix (e.g. restart without patching; resubmit
   without cleaning) → not ok. Also no-op → not ok.
4. `test_leak`: for every tool call on every M1 scenario, output contains no fault label string, no
   truth field, no fixture path, and no fix hint; fix tools return identical ack text regardless
   of correctness; config shown to the agent has no fault-named key.
5. `test_evidence_ids_opaque`: ids don't change when the fault label changes but the record text is
   identical (i.e. id depends on seed+index only).
6. `test_tools_truncation_and_observed_ids`: observed_ids == ids present in returned text.
7. Episode plumbing: reset/step/state round-trip; submit_diagnosis shape validation.
Mark slow executed tests `@pytest.mark.executed`; whole suite should run < ~3 min on the Mac.

## Out of scope for M1

Simulator overlay, remaining 7 faults, generator splits, V0/V1/V2, audit suite, adapters, bundle
renderer. Don't build hooks for them beyond the interfaces above.
