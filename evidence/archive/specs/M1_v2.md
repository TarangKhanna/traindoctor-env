# M1 v2 spec — Task A and Task B (supersedes the 4-fault M1 scope)

Read with the design spec (docs/DESIGN_NOTES.md) (replay validity), §6.2a, §6.3–6.4, §7 and the project rules. Build on branch
`m1-executable-job`: keep launcher, manifest, snapshot capture, Replay, reference-run checksums and
the recovery invariants; rework fault injection. The 4 old faults stay in the tree as M2 candidates
(mark them, don't delete; their tests may stay if green and fast).

## 0. Principle: faults live in real code

The job is a small source tree (`jobs/template/`: `train.py`, `data.py` with a sampler, `ckpt.py`,
`config.yaml`). A scenario = template + a seeded **source/config patch** that introduces the bug.
No hidden injection knobs. The agent (Tier B) sees and edits this source; the verifier never trusts
the agent's code for the reference — the reference run always uses the pristine template.

## 1. Task A — same timeout, two causes

- **A1 inconsistent collectives:** a rank-dependent code path (in `train.py`, e.g. a conditional
  metrics/grad-sync branch keyed on rank or on a per-rank config value) makes one rank call a
  different collective. Peers: COLLECTIVE_TIMEOUT.
- **A2 rank stalled before communication:** one rank blocks in its data/compute path and never
  enters the collective — e.g. `data.py` retry-waits on a shard file whose path is wrong for that
  rank only (bad per-rank shard mapping in config), with a wait loop that never times out. Peers:
  COLLECTIVE_TIMEOUT; the stalled rank is killed by the watchdog.
- Indistinguishable by `job_status` and peer errors alone (test asserts the canonical job-level
  symptom is identical for an A1/A2 pair). Distinguishing evidence: A1 — the divergent rank
  *entered* a different op at seq N; A2 — the stalled rank never entered seq N and its last log
  is in the data path. Both need a real repair (fix the branch / fix the shard mapping or the
  wait), then relaunch from the latest valid checkpoint, and the job must complete with the
  recovery invariants (params/optimizer bit-identical to reference, no duplicate updates, lost
  work ≤ ckpt interval, ranks consistent).
- Wrong fixes that must fail: raising the PG timeout (A1 still mismatches; A2 still stalls —
  unless the stall is finite, so make it infinite), restart without repair, repairing the wrong
  cause (A1 fix applied to an A2 scenario), killing/excluding the rank (changes world size →
  params mismatch).

## 2. Task B — restart with checkpoint/sampler inconsistency

- After a worker failure (launcher kills a rank at a seeded step after ≥1 checkpoint), the job
  auto-restarts from the latest checkpoint and runs to completion; loss looks normal.
- Bug variants in `ckpt.py`/`data.py`: **B-skip** (sampler offset restored from the last *logged*
  step rather than the checkpoint step → samples between ckpt and failure never trained on);
  **B-dup** (sampler state not saved → restarts from epoch start → samples replayed).
- Control: **B-ok** — same failure and restart with consistent state; the correct answer is "no
  repair needed" (any code change that alters training fails the invariants).
- Every step logs committed sample IDs per rank (`samples.jsonl`). Verifier checks, against the
  uninterrupted reference: per-step committed sample IDs (no skip, no duplicate), step counts,
  restored model/optimizer/sampler state, final params bit-identical.
- Repair = fix save/restore so sampler state is checkpointed and restored, then re-run recovery
  from the last valid checkpoint *before* the corruption (the completed corrupted run is not a
  valid result). Blanket restart or "resume again" must fail.

## 3. Tiers

- **Tier B (strong agents):** isolated workspace copy: `job/` (patched source + config), `runs/<id>/`
  (logs, traces, samples, events of the failed run), `ckpt/`. Agent may read and edit anything in
  the workspace and call `relaunch` (resubmit path, with watchdog). Replay validity: reads after an
  edit+relaunch come from that run's fresh artifacts. Final verification re-executes the agent's
  final `job/` through the standard recovery protocol and checks the invariants.
- **Tier A (RL projection):** bundle of the same snapshot + a menu of K candidate repairs (each a
  concrete diff or action sequence, IDs opaque, order seeded): exactly the correct one(s), plus
  distractors (raise timeout, restart only, fix the other cause, exclude rank, no-op). Answer =
  label + evidence IDs + repair ID. Outcome of each menu item precomputed by real re-execution
  (the fix-outcome table) and spot-checked live.

## 4. Verifier ladder (the design spec (docs/DESIGN_NOTES.md))

V0 label; V1 label + cited ⊆ observed + mechanism evidence predicate; V2 V1 + verified repair with
preserved correctness (invariants above). Emit all three per episode, plus components.

## 5. Tests (rules, not snapshots)

Reproducible from seed (byte-identical public snapshot ×2); A1/A2 same job-level symptom; each
oracle repair passes all invariants; each listed wrong fix fails with the right invariant flagged;
B-ok: no-change passes, any training-altering change fails; samples.jsonl reference-vs-recovered
checks catch B-skip and B-dup; leak test over workspace (no truth, no template-vs-patch hints like
"BUG"/"inject"/"fault" comments, no git history of the patch); Tier A menu outcomes match live
re-execution; Episode ≡ verify_fix verdict equivalence. Suite < ~4 min.

## 6. Must-fix from the Codex xhigh review of the 4-fault M1 (apply to the shared infra)

1. **[P1] Seed leaks the label:** `job_config` exposed `seed` and label = `LABELS[seed % 4]`. Scenario
   selection must use a private RNG stream; every public value (job seed, IDs, ports, names, ordering)
   comes from streams independent of task/variant choice. Regression test: across ≥40 scenarios, no
   public field (or simple function of it, e.g. mod-k of any integer) predicts the label better than
   chance; and the public seed itself is not shown unless needed.
2. **[P1] Multi-attempt rollback hides lost work:** verification checked only the final run. Track
   applied steps and rollbacks across EVERY recovery attempt in the episode; lost work = total steps
   recomputed beyond the last valid checkpoint over all attempts; manifest dedup must not erase this
   history. Test: correct patch → keyless resubmit from zero → dedup → restart from latest must FAIL.
3. **[P2] Idempotent retry after success invalidates recovery:** a repeated idempotent resubmit must
   keep (or reload) the completed job state. Test: oracle + duplicate idempotent resubmit passes.
4. **[P2] Stale-lock liveness uses ambient PIDs:** lock ownership in replay must use captured owner
   state / a replay-owned identity, never `os.kill(pid, 0)` on a frozen PID. Test with a reused PID.
