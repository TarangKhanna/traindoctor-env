# M1.5 spec — frontier gap probe (before M2 breadth)

Question: on the 4 executed M1 faults, do strong coding agents (Claude Code, Codex CLI) show a
**substantive** gap — wrong fix, lost progress, ungrounded evidence, unnecessary destructive action —
or only interface friction? Decides how M2 is shaped. Subscription auth only; no API keys.

## 1. Tool surface: one MCP stdio server over the plain Episode

`adapters/mcp/server.py` (FastMCP, `fastmcp>=3,<4` as OpenEnv pins): exposes exactly the Episode
tools (reads, fixes, `submit_diagnosis`, `finish`) with their M1 argument schemas, one episode per
server process, scenario chosen by an env var / CLI arg the harness sets. Writes the episode
trajectory (every tool call + returned text + observed IDs) to a JSONL the harness owns. This
server is reused by the OpenEnv adapter in M3 — keep it thin.

## 2. Answer isolation (load-bearing — results are void without it)

Agents must not be able to read `truth.json`, the private fixture, the oracle, or the repo's
`jobs/faults/` source for the scenario.
- Scenario store lives outside the agent's working directory (agent cwd = fresh empty temp dir).
- **Claude Code:** `claude -p --mcp-config <cfg> --strict-mcp-config --allowedTools "mcp__traindoctor__*"`
  (verify flag names with `claude --help`), no Bash/Read/Edit tools; `--output-format stream-json`.
- **Codex:** verify whether a filesystem permission profile (the `[permissions.<name>.filesystem]`
  mechanism already used in ~/.codex/config.toml, path = "none") can deny reads of the scenario store
  and repo while the MCP server (spawned by Codex) can still read it. Run Codex via `codex exec --json`
  with a per-run `-c` / `--profile` override — do not edit the user's global config.
- **Always**, both agents: scan the full trajectory for any access to hidden paths or file names
  (truth, fixture, faults, oracle). Any hit → episode marked CONTAMINATED, excluded, and counted.
- Write a canary test: a deliberately leaked canary string placed in the hidden store must never
  appear in any trajectory.

## 3. Scenarios and baselines

- 12 scenarios = the 4 M1 faults × variants × seeds, arranged as pairs that look alike on the
  surface (e.g. both COLLECTIVE_MISMATCH variants vs a SHARDING_MISCONFIG crash with similar job_status;
  PREEMPTION_NO_CLEANUP vs NONIDEMPOTENT_RESUBMIT, which share the preemption history).
- Agents: Claude Code (default model), Codex (gpt-6.1-sol, record effort). k=2 attempts each.
  Same system prompt: the task, the tool list, "diagnose, repair, and submit"; a per-episode budget
  (max tool calls, e.g. 40; wall clock e.g. 10 min).
- Baselines (no LLM): oracle; deterministic **runbook** solver (standard triage order: status →
  errors → trace → config diff → lock/manifest → fix); restart-everything; no-op.
- Optional third arm: agents given the runbook text in the prompt.

## 4. Scoring (M1 pieces only; full V2 arrives in M2)

Per episode: label correct; evidence cited ⊆ observed; fix outcome from `verify_fix` /
Episode `outcome()` with all recovery invariants (params match reference, no duplicate updates,
lost_steps, ranks consistent); destructive actions used; tool calls; wall time; contaminated flag.
Results → `results/m1_5/` (JSONL per episode + run config incl. CLI versions, model, effort,
budgets, git SHA) and a `scripts/m1_5_summary.py` table. Every reported number comes from that script.

## 5. Decision output (`docs/m1_5_findings.md`)

Per agent: label acc, recovery-correct rate, evidence-grounded rate, destructive-action rate,
failure modes with 2–3 quoted trajectory excerpts. Verdict: SUBSTANTIVE GAP / FRICTION ONLY /
SOLVED. If SOLVED or FRICTION ONLY: list the ambiguity knobs M2 must add first.

## Cost / safety

Subscription runs only, k=2 × 12 × 2 agents = 48 episodes; ask before scaling beyond that.
No model process runs locally during this probe (MLX benchmarks must be idle or finished).
